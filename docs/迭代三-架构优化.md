# 迭代三 — Agent 架构优化说明（成员5）

> 主责：混合 workflow、runMode 路由、Multi-Agent 协调。  
> 接口单一事实来源：`lib/agent/contracts.ts`

---

## 一、优化目标与问题

迭代二 Agent 每次用户消息均走完整 **Plan-Execute + ReAct + Reflexion**，存在：

| 问题 | 表现 | 影响 |
|------|------|------|
| 延迟高 | 「南京天气怎么样」也 draftPlan + 多步 ReAct | 简单问答 30s+ |
| 成本高 | 追问「改第二天慢节奏」触发全量 replan | token 与 LLM 调用浪费 |
| 体验差 | 复述 Day2 内容仍重新规划 | 回答冗长、偏离意图 |

**优化思路**：在 orchestrator 外层增加 **runMode 路由**，按意图分发到三种工作流。

---

## 二、架构总览

```
用户消息
    ↓
RunModeRouter.decide()          ← 启发式（无 LLM 开销）
    ↓
RunModeRoutingAgent.run()
    ├── full_plan_execute  → PlanExecuteOrchestrator / MultiAgentCoordinator
    ├── incremental_revise → IncrementalReviseWorkflow
    └── quick_reply        → LightweightWorkflow（可选 0～1 次工具）
    ↓
ReasoningEvent 流 → Convex trace → assistant 消息
```

### 2.1 三种 runMode 边界

| runMode | 适用场景 | 行为 | 典型 latency |
|---------|----------|------|--------------|
| `full_plan_execute` | 首轮规划、大幅变更、强制重规划 | draftPlan → revisePlan → 逐步 ReAct → 总结 | 高 |
| `incremental_revise` | 已有方案上的局部修改（改某天、调预算） | 单次 LLM 修订 Markdown 全程方案，**无 plan_draft** | 中 |
| `quick_reply` | 复述、简单问答、单点天气 | 单次 LLM；天气类可调用 **1 次** `weather_forecast` | 低 |

### 2.2 与 Plan-Execute / ReAct / Workflow 的关系

- **Plan-Execute**：`full_plan_execute` 模式，适合结构化多步任务（完整行程规划）。
- **ReAct**：嵌在 Plan-Execute 的每步执行中（`ReactExecutor`），不在 quick/incremental 中展开。
- **Workflow**：`incremental_revise` 与 `quick_reply` 为轻量固定流程（少分支、低延迟），属于混合架构中的「快捷路径」。

## 三、实现细节

### 3.1 接口（contracts.ts）

- `AgentRunMode`：三种运行模式枚举
- `IRunModeRouter`：路由决策接口
- `AgentRole` / `IMultiAgentCoordinator`：Multi-Agent 可选扩展
- `ReasoningEvent.type = "run_mode" | "agent_handoff"`：可视化路由与角色切换

### 3.2 RunModeRouter（启发式）

文件：`lib/agent/orchestrator/RunModeRouter.ts`

路由规则（优先级从高到低）：

1. 含「重新规划 / 从头 / 重做」→ `full_plan_execute`
2. 简单问答（天气、问候、介绍）且无规划/修订意图 → `quick_reply`
3. 无已有方案 + 含规划关键词 → `full_plan_execute`
4. 有已有方案 + 复述 → `quick_reply`
5. 有已有方案 + 修订关键词 → `incremental_revise`
6. 短句（≤80 字）且无复杂意图 → `quick_reply`
7. 默认 → `full_plan_execute`

`hasExistingPlan` 由 Convex action 根据 `conversations.tripPlanMarkdown` 或 history 中最近完整 itinerary 判定。

### 3.3 RunModeRoutingAgent

文件：`lib/agent/orchestrator/RunModeRoutingAgent.ts`

- 读取 `AgentRunInput.runMode`（前端可 override，否则 action 内调用 `decideRunMode`）
- 分发到对应 `IAutonomousAgent` 实现
- `full_plan_execute` 的 `run_done.updatesMasterPlan = true`

### 3.4 IncrementalReviseWorkflow

- 从 `contextBundle.workingMemory` 读取 `tripPlanMarkdown`
- 单次 LLM 输出修订后完整 Markdown
- trace **不出现** `plan_draft`（满足 MT-2 验收）

### 3.5 LightweightWorkflow

- 默认纯 LLM，不调用规划器
- 匹配天气问句且工具已启用时，最多调用 1 次 `weather_forecast`
- `run_done.updatesMasterPlan = false`，不覆盖已有全程方案

### 3.6 MultiAgentCoordinator（可选亮点）

环境变量 `USE_MULTI_AGENT=true` 时，`full_plan_execute` 改用协调器：

```
planner (draftPlan + revisePlan)
    → agent_handoff → tool_runner (ReAct 逐步执行)
    → agent_handoff → summarizer (buildRunDoneSummary)
```

便于答辩演示「多角色协作」与 trace 中的 `agent_handoff` 事件。

### 3.7 Factory 依赖注入

文件：`lib/agent/orchestrator/factory.ts`

```typescript
createAutonomousAgentPipeline(traceSink?, deps?: {
  skillRegistry?: ISkillRegistry;      // 成员1
  knowledgeService?: IKnowledgeService; // 成员2
  contextEngine?: IContextEngine;       // 成员4
  toolRegistry?: IToolRegistry;         // 成员6
  runModeRouter?: IRunModeRouter;
})
```

成员5 **仅改 factory 组装**；其他成员通过 `deps` 注入，不在 orchestrator 内 `new` 具体类。

## 五、验收用例对照

| ID | 输入 | 期望 runMode | 期望 trace 特征 |
|----|------|--------------|-----------------|
| MT-1 | 「规划南京 3 日游，预算 3000」 | `full_plan_execute` | 有 plan_draft、tool_call |

## 六、优化前后对比（预估）

| 指标 | 优化前（全量 Plan-Execute） | 优化后 |
|------|----------------------------|--------|
| 简单天气问句 latency | ~25–40s | ~3–8s（1 LLM + 可选 1 工具） |
| 局部修订 LLM 调用 | draft + revise + N×ReAct | 1 次 LLM |
| 复述行程 token | 全量规划 prompt | 仅 history + tripPlan |

> 正式数据可在 W5 用 eval 平台对同一 session 对比 `latency_ms` 与 trace 事件数。

---

## 七、随机性应对

1. **路由误判**：前端可传 `runMode` override；日志中记录 `run_mode` 事件便于复盘。
2. **LLM 修订漏改/多改**：`incremental_revise` system prompt 强调「仅改用户提及部分」；失败时可手动选「重新规划」触发 `full_plan_execute`。
3. **Multi-Agent 与单 Orchestrator 行为差异**：默认关闭 `USE_MULTI_AGENT`；评测入口 `runAgentEval` 不传 `runMode` 时仍走 `full_plan_execute`，与迭代二兼容。
