# 迭代三成员二：跨对话知识共享与 RAG 知识增强

## 实现范围

- 长期记忆：`userMemories` 表保存用户偏好、事实、约束和其他记忆，支持手动 CRUD 与运行后自动抽取。
- 跨对话开关：`conversations.sharedKnowledgeEnabled` 为 `true` 时读取用户全部长期记忆；为 `false` 时只读取当前对话抽取的记忆。
- RAG 知识库：`knowledgeDocuments` 保存用户上传文档；**内置知识库**（南京/珠海攻略、通用出行、高铁换乘等 6 份）随 Agent 自带，检索时自动合并。
- **按需检索**：`shouldRetrieveKnowledge()` 在完整规划时默认检索；复述/天气/纯日程修订跳过；攻略类问答才检索。
- **出处标注**：Prompt 要求保留 `[来源: {documentTitle} · {citation}]`；`ensureKnowledgeCitations()` 在 LLM 遗漏时自动追加。
- **动态更新**：`updateDocument` 修改正文后自动重建分块；`rebuildDocument` 可手动重建索引。

## 关键文件

- Convex schema：`convex/schema.ts`
- 长期记忆 API：`convex/memories.ts`
- 知识库 API：`convex/knowledge.ts`（upload / update / rebuild / retrieve）
- 纯函数服务层：`lib/agent/knowledge/`（含 `builtinKnowledge.ts` 内置攻略）（检索、分块、出处、按需检索）
- 设置页：`app/settings/memory/page.tsx`、`app/settings/knowledge/page.tsx`
- Agent 接入：`convex/agent.ts`、`lib/agent/plan/LLMPlanGenerator.ts`、`lib/agent/orchestrator/finalTravelSummary.ts`
- Trace 事件：`knowledge_retrieved`（可在运行轨迹中看到检索/query/命中文档）

## 使用与验收

### 1. 跨对话记忆（任务一加分）

1. 在 `/settings/memory` 手动新增「用户不吃辣」。
2. 在对话页开启「共享长期记忆」，新开对话询问「推荐南京晚餐美食」，回答应避开辣味。
3. 关闭共享后，新对话不应引用其他对话的私有记忆。

### 2. RAG 知识库（含内置 + 可选上传）

1. 打开 `/settings/knowledge`，列表应显示 **6 份内置文档**（南京慢游、珠海浪漫、通用出行等），无需上传即可检索。
2. （可选）再上传自定义 Markdown 攻略；检索时会与内置内容合并。
3. 「检索预览」输入：`南京晚上适合去哪` 或 `珠海野狸岛夜景` → 应召回内置分块。

### 3. 出处标注（任务二 RAG ②）

1. 在同一会话询问：`南京三日慢游有什么适合晚上安排的地点？`
2. 打开 Trace，应看到 **知识检索** 事件（非 skipped，chunkCount ≥ 1）。
3. 助手回答正文应包含类似：`[来源: 南京慢游攻略 · 第 1 段]`（若 LLM 未写，末尾会自动追加 **参考来源** 区块）。

### 3.1 评测数据集

见 `docs/eval-datasets/iter3-rag-cross-memory.json` 用例 `rag-citation-nanjing-guide`。

### 4. 动态更新知识（任务二 RAG ③）

1. 在知识文档列表点击 **编辑**，修改正文（如把「老门东」改为「老门东 + 秦淮河夜游」）并 **保存并重建索引**。
2. 再次检索预览或对话提问，回答应反映新内容。

### 5. 按需检索（不应误检索）

- 输入「渔女加入第三天日程」（增量修订）：Trace 中 **知识检索** 应显示 `skipped: true`。
- 输入「从南京去珠海玩」（完整规划）：应执行检索（即使暂无命中）。

## 说明

当前 RAG 为关键词检索 MVP，便于本地和课程演示稳定运行。后续可将 `knowledgeChunks` 增加 embedding 字段或外部向量库，并在 `retrieveForUser` 中替换排序逻辑。城市过滤无命中时会 **回退全库检索**，避免目的地标签与文档 city 不一致导致零召回。
