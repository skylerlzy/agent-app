# 迭代三成员二：跨对话知识共享与 RAG 知识增强

## 实现范围

- 长期记忆：`userMemories` 表保存用户偏好、事实、约束和其他记忆，支持手动 CRUD 与运行后自动抽取。
- 跨对话开关：`conversations.sharedKnowledgeEnabled` 为 `true` 时读取用户全部长期记忆；为 `false` 时只读取当前对话抽取的记忆。
- RAG 知识库：`knowledgeDocuments` 保存原文元数据，`knowledgeChunks` 保存分块文本。当前版本采用关键词检索，避免引入额外 embedding 服务。
- 出处标注：RAG 片段以 `[来源: {documentTitle} · {citation}]` 注入 prompt，最终回答被要求保留该格式。

## 关键文件

- Convex schema：`convex/schema.ts`
- 长期记忆 API：`convex/memories.ts`
- 知识库 API：`convex/knowledge.ts`
- 纯函数服务层：`lib/agent/knowledge/`
- 设置页：`app/settings/memory/page.tsx`、`app/settings/knowledge/page.tsx`
- Agent 接入：`convex/agent.ts`、`lib/agent/plan/LLMPlanGenerator.ts`、`lib/agent/orchestrator/finalTravelSummary.ts`

## 使用与验收

1. 在 `/settings/memory` 手动新增“用户不吃辣”。
2. 在对话页开启“共享长期记忆”，新开一个对话询问南京美食，回答应避开辣味推荐。
3. 关闭“共享长期记忆”，新对话不应再引用其他对话的私有记忆。
4. 在 `/settings/knowledge` 上传南京攻略 Markdown 或纯文本，使用“检索预览”确认能召回相关片段。
5. 对话中询问攻略覆盖的问题，最终回答应包含 `[来源: …]` 标记。

## 说明

当前 RAG 为关键词检索 MVP，便于本地和课程演示稳定运行。后续可将 `knowledgeChunks` 增加 embedding 字段或外部向量库引用，并在 `convex/knowledge.ts` 的 `retrieveInternal` 中替换排序逻辑。
