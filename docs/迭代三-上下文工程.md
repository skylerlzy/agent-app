# 迭代三 — 上下文工程说明（成员4）

> 主责：滑动窗口、摘要压缩、记忆分层注入。  
> 接口单一事实来源：`lib/agent/contracts.ts`

## 一、目标

多轮出行规划会持续累积用户约束、助手方案、工具观测、长期记忆和知识库片段。如果每轮都把完整历史塞进 LLM，会带来：

| 问题 | 表现 | 影响 |
|------|------|------|
| token 膨胀 | 20 轮后 prompt 过长 | 延迟上升，甚至超上下文 |
| 约束遗忘 | 早期「预算 2000」「不吃辣」被窗口裁掉 | 规划与用户偏好冲突 |
| 注入分散 | planner / quick / revise 各自拼上下文 | 难统一调试和验收 |

成员4的优化目标是把上下文整理成稳定结构：**摘要承接旧历史，工作记忆保存当前行程，长期记忆/RAG 分层注入，近期窗口保留可对话性**。

## 二、实现文件

```
lib/agent/context/
├── ContextEngine.ts          # IContextEngine 实现：compose + optimizeAgentInput
├── estimateTokens.ts         # 轻量 token 估算与预算读取
├── index.ts                  # 上下文模块导出
├── formatHistoryForPrompt.ts # 既有 history/summary 格式化工具
└── tripPlanMemory.ts         # 当前行程 workingMemory 特化工具
```

接入点：

```
convex/agent.ts
  buildAgentInputForConversation()
    ↓
  注入 longTermMemories / ragChunks / tripPlan workingMemory
    ↓
  ContextEngine.optimizeAgentInput()
    ↓
  如 updatedSummary 非空，写回 conversations.summary
    ↓
  pipeline.run(input)
```

## 三、核心策略

### 3.1 Token 估算

`estimateTokens.ts` 使用轻量估算：

- 中文字符按约 `0.75 token / char`
- ASCII 按约 `4 char / token`
- 每条 message 额外计入少量结构开销

默认预算为 `6000`，可通过 Convex/本地环境变量调整：

```bash
AGENT_CONTEXT_TOKEN_BUDGET=6000
```

### 3.2 分层注入

`ContextEngine.compose()` 固定按以下优先级组织上下文：

1. `systemBase`：调用方给出的基础系统指令
2. `conversationSummary`：早期对话摘要
3. `workingMemory`：当前完整行程、槽位或进行中方案
4. `longTermMemories`：跨对话偏好、事实、约束
5. `ragChunks`：知识库片段与 `[来源: ...]` 标记
6. recent history：从最近消息向前填充，直到预算上限
7. current user text：本轮用户输入

这样能保证预算紧张时优先保留「长期约束」和「当前行程」，而不是被冗长历史挤掉。

### 3.3 滑动窗口

近期历史默认最多保留 20 条。实际保留数量由 token budget 决定：

- 从最新消息向前选择
- 超预算时停止
- 如果连最新一条都太长，则截断该条而不是完全丢失

### 3.4 摘要压缩

触发条件：

- 原始 history token 估算超过 `tokenBudget * 0.6`
- 或有消息因预算被裁掉

当前实现优先使用确定性摘要 fallback，抽取预算、忌口、偏好、同行人、日期、住宿、交通、节奏等关键词句。`ContextEngine` 也预留了 `summarizer?: ILLMClient`，后续可切换为 LLM 摘要而不改接口。

生成的 `updatedSummary` 会在 `convex/agent.ts` 中写回：

```
conversations.summary
```

同时，本轮 `input.contextBundle.conversationSummary` 会使用新摘要，保证同一轮后续 planner / quick / revise 都能读到压缩后的约束。

### 3.5 工作记忆

当前代码已有出行场景特化 working memory：

```typescript
buildWorkingMemoryWithTripPlan(tripPlanMarkdown)
parseTripPlanFromWorkingMemory(workingMemory)
```

Convex action 会优先从 `conversations.tripPlanMarkdown` 读取完整行程，并注入到 `contextBundle.workingMemory`。这满足增量修订与复述类问题对“当前全程方案”的依赖。

## 四、与其他成员边界

| 成员 | 协作方式 |
|------|----------|
| 成员1 Skill | Skill 仍由 action 解析为 `skillSystemSection`；上下文工程不负责 Skill CRUD |
| 成员2 记忆/RAG | 只消费 `longTermMemories` / `ragChunks`，不直接管理表 |
| 成员3 对话 | 只消费 `messages` 形成的 history；摘要写回走已有 internal mutation |
| 成员5 架构 | 不改 runMode 分支，只在 pipeline 前优化 `AgentRunInput` |
| 成员6 工具 | 不改工具注册，只保证工具相关结论能留在工作记忆/近期上下文中 |

## 五、验收对应

| 验收项 | 实现对应 |
|--------|----------|
| 20 轮对话后仍记住「预算 2000」 | 超窗口内容进入 `conversations.summary`；长期记忆由成员2注入 |
| `estimatedTokens` 不超过预算 | `ContextEngine.optimizeAgentInput()` 写入 `contextBundle.estimatedTokens` |
| 摘要更新后 DB 非空 | `convex/agent.ts` 检测 `updatedSummary` 后 patch `conversations.summary` |

## 六、演示建议

1. 在同一对话连续输入多个约束，例如预算、忌口、节奏、住宿。
2. 连续追问超过 20 轮或输入较长文本。
3. 查看 Convex `conversations.summary` 是否出现摘要。
4. 再问「按我前面预算调整一下」，观察回答是否承接早期预算。

## 七、后续增强

- 将 fallback 摘要切换为 `OpenAICompatibleClient` 的 LLM 摘要。

- 在 trace 中增加上下文预算事件，例如 `context_compacted`，便于前端可视化。
- 用 eval 数据集记录优化前后 prompt token、latency、约束命中率。
