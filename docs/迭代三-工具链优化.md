# 迭代三 · 工具链重构与扩展（成员6）

> 接口单一事实来源：`lib/agent/contracts.ts`（`TOOL_NAMES`、`UserToolSetting`、`IToolRegistry`）。

## 一、问题发现（优化前）

| 现象 | 影响 | 关联指标 |
|------|------|----------|
| 仅 2 个工具，description 冗长且边界不清 | LLM 误选 maps 查跨城高铁、重复调 weather | tool_correctness ↓ |
| 无参数前置校验 | 非法 city/空 OD 直接打 HTTP，Reflexion 轮次浪费 | latency ↑ |
| 用户无法关闭工具 | 无法满足产品化「管理工具」与 MT-6 验收 | — |
| 缺少 POI 检索 | 规划阶段依赖 LLM 臆造景点名 | factuality ↓ |

## 二、实现细节

### 2.1 契约扩展

- `TOOL_NAMES` 增加 `poi_search`、`rail_schedule_hint`
- `UserToolSetting` + Convex 表 `userToolSettings`
- `IToolRegistry.listForUser` / `createConfigurableToolRegistry`
- `IToolArgumentValidator`（`ToolArgumentValidator` 类）

### 2.2 工具实现

| 工具 | 实现 | 降级/校验 |
|------|------|-----------|
| `weather_forecast` | 和风（沿用） | dateIso 格式校验；超 30 日 note + doNotRetry |
| `maps_route_estimate` | 高德路径（沿用） | transit→driving；OVER_DIRECTION_RANGE 粗估 |
| `poi_search` | 高德 `place/text` | 失败 `retryable: true` + 明确 message |
| `rail_schedule_hint` | 规则提示 + 免责声明 | 非 12306 实时数据 |

集中描述：`lib/agent/tools/descriptions.ts`

### 2.3 运行时过滤链

```
用户设置页 userToolSettings（全局默认）
    ↓
对话 enabledToolNames（空 = 跟随全局）
    ↓
createConfigurableToolRegistry → ReactExecutor / LightweightWorkflow
    ↓
仅暴露已启用工具给 LLM（plan suggestedTools 同步过滤）
```

### 2.4 产品化

- 路由：`/settings/tools`（`ToolsPanel`）
- 对话页：`ToolPicker` 按会话覆盖
- Convex：`toolSettings.list` / `setEnabled` / `checkEnvStatus`

## 三、优化前后对比（eval 数据集 `docs/eval-datasets/iter3-tools-correctness.json`）

| Case | 优化前期望问题 | 优化后期望 |
|------|----------------|------------|
| T-01 跨城高铁 transit | maps 被误调 | validator 拦截或改用 rail_schedule_hint |
| T-02 空 city 天气 | HTTP/geo 失败 | WEATHER_CITY_REQUIRED + reflexion |
| T-03 南京景点规划 | 无 POI 数据 | poi_search 返回结构化列表 |
| T-04 关闭 weather | 仍出现 tool_call | trace 无 weather_forecast（MT-6） |

建议在 `agent-eval-platform` 中对同一数据集对比 **tool_correctness** 与 **平均 ReAct 轮次**。
